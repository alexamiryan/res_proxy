# Tailnet membership inside ResProxy (Android)

Status: implemented on Android (2026-11-22). Deviations from the plan below:

- tsnet's own loopback SOCKS5 (`Server.Loopback`) is not used: its dialer sends non-tailnet addresses straight out of
  the app process, past the proxy. `internal/tailnet` runs its own SOCKS5 front whose dialer only dials known peers.
- Settings field names: `acceptInbound` (any port, services on all interfaces, via the TUN address) and
  `loopbackPorts` (explicit 127.0.0.1 opt-in) instead of a single `inboundPorts`.
- `ts_omit_*` build tags save only ~0.7 MB of ~22 MB per ABI and were not used.
- Found in the spike: tailscale's log setup panics in an app (no HOME / TMPDIR); `TS_LOGS_DIR` and `TMPDIR` now point
  into the node's directory. A Go panic takes the whole process down, so the controller leaves the tailnet off after a
  crash during start.
- Verified on an Android 16 emulator against a local test tailnet (`cmd/tailnettest`): login URL from Tailscale's real
  control server, joining, outbound by short name / MagicDNS name / IP, inbound to an all-interfaces listener, loopback
  listener refused unless listed, Wi-Fi switch, disconnect / reconnect keeping the device. Not yet tried on a phone or
  against a real tailnet.

Original plan:

## Goal

The phone joins the user's tailnet from inside ResProxy, so the Tailscale app is no longer needed (Android allows
one VpnService; ResProxy owns it, so the two apps can never run together). Afterwards:

- the phone is reachable from tailnet peers at its Tailscale IP / MagicDNS name (TCP to any port a local app listens on);
- apps on the phone reach tailnet peers by Tailscale IP or MagicDNS name;
- everything else still goes TUN → hev → relay → [WireGuard →] residential proxy, exactly as today.

Scope statements:

- Tailnet-bound traffic does **not** go through the residential proxy. Neither does the tailnet's own underlay
  (control server, DERP, peer WireGuard, STUN): it leaves the app process, which is excluded from its own VPN, so it
  goes direct, which is what a tailnet needs (UDP, hole punching).
- v1 is TCP only in both directions. No exit-node use, no subnet routes, no Tailscale SSH, no Funnel.
- Android only. iOS can't fit tsnet in the ~50 MB network-extension budget next to hev and the WireGuard netstack;
  Chrome has no need. Both only carry the settings fields for backup round trips.

## Approach

Embed **tsnet** (`tailscale.com/tsnet`, userspace Tailscale on gVisor netstack, no TUN) in the existing Go bridge
`native/wgbridge` (`libwgbridge.so`). It gives us everything we need without touching the TUN:

- `Server.Loopback()` starts a loopback SOCKS5 (user `tsnet`, random password) that dials into the tailnet and
  resolves MagicDNS names itself. The Kotlin relay uses it through the existing `Socks5Client` for tailnet targets.
- `Server.RegisterFallbackTCPHandler(cb)` is a catch-all for inbound TCP: `cb(src, dst)` returns a handler that
  dials `127.0.0.1:<dst.Port>` on the phone, so any local server (Termux sshd 8022, LocalSend, Syncthing, KDE
  Connect, a dev server) is reachable without configuration. No inbound UDP hook exists (v1 gap).
- `Server.LocalClient()` gives status (state, auth URL, self IPs/DNS name, peers, MagicDNS suffix) for the UI and
  the dispatch table.
- `Server.Sys().NetMon.InjectEvent()` is called from our network-change callback, so tsnet re-probes paths at once.

Lifecycle is separate from the proxy tunnel's: tsnet starts when the service connects (if enabled) and stops on
Disconnect or when the feature is turned off. Repairs, chain rebuilds, hev restarts and `fail()` never touch it, and
a tsnet problem never fails the tunnel (it is shown on the Tailnet page and logged).

## Spike first (decides feasibility; 1–2 days)

Run the spike **inside the app process** (a debug JNI entry behind a Settings → Diagnostics button), never from
`adb shell`: the shell uid has netlink and SELinux permissions a normal app lacks (Android 11+ blocks `RTM_GETLINK`
for apps, which is what Go's `net.Interfaces()` uses), so a shell run would pass and prove nothing. Check:

1. tsnet runs as a plain non-root app process. netmon on Android falls back to polling (`net/netmon/polling.go` builds
   for everything but windows/darwin), but interface enumeration is the real question. The Tailscale Android app feeds
   interfaces from Java through a netmon hook: check `net/netmon` for `RegisterInterfaceGetter` (or its current name)
   and, if present, supply the list from Kotlin's `NetworkInterface.getNetworkInterfaces()` via JNI. Then confirm a
   peer handshake completes (direct and via DERP) and that a Wi-Fi ↔ mobile switch recovers after `InjectEvent()`.
   This item decides the "yes".
2. `Loopback()` SOCKS5: connect to a peer by 100.x IP, by `name.tailnet.ts.net` and by bare `name`.
3. `RegisterFallbackTCPHandler`: `ssh phone-ip -p 8022` from a laptop reaches Termux. Check that ICMP ping to the
   phone's tailnet IP is answered by netstack (nice for "is it up", not required).
4. Log upload: tsnet uploads logs to `log.tailscale.com` by default. Find the current switch (`TS_NO_LOGS_NO_SUPPORT`
   env / `ts_omit_logtail` build tag / `Server.Logf`) and turn it off; this is a privacy app.
5. Size and deps: `go.mod` pulls `tailscale.com` v1.104.x with its own wireguard-go fork and gVisor pin; check the
   gVisor version against `golang.zx2c4.com/wireguard/tun/netstack` (tailscale's `replace` directives don't propagate
   to us). Measure the stripped `.so` per ABI with `ts_omit_*` tags (aws, bird, tap, kube, ssh, webclient, capture,
   relayserver, …). Expect tens of MB per ABI; decide whether to drop x86/armeabi-v7a (sideloaded app) or use ABI splits.
6. Memory: RSS of the service with tsnet idle and under transfer (Android is not as tight as iOS, but note it).

If 1–3 pass, the rest is engineering.

## Phase 1: make room (no feature yet)

- **Move hev's fake-IP range.** `HevConfig` hands out 100.64.0.0/10, which is exactly Tailscale's CGNAT range, and
  `LocalSocksServer.isFakeDnsIp` already refuses every 100.64–127.x destination with reply 4. Switch mapdns to
  `198.19.0.0/16` (next to the 198.18.0.x TUN addresses; verify hev accepts the network/netmask), update
  `isFakeDnsIp`, its unit tests, the `Routes.kt` comment and the AGENTS.md gotcha. 198.18/15 is routed into the TUN in
  both LAN modes already.
- **IPv6 route.** Tailscale's ULA `fd7a:115c:a1e0::/48` sits under `fd00::/8`, which `Routes.LAN_V6` keeps out of the
  TUN with LAN bypass on. Add that /48 as an explicit route after the complement (or declare IPv6 tailnet out of v1).
- Go bridge: give tsnet its own state and mutex in a new `tailnet.go`; `start()`/`stop()` in `main.go` (WireGuard
  chain) must not clear it.

## Phase 2: Go bridge

`native/wgbridge/tailnet.go`, JNI exports on a new Kotlin object `dev.resproxy.net.Tailnet`:

| Export | Does |
|---|---|
| `nativeTsStart(dir, hostname, authKey, controlURL, stateKeyHex)` | Creates `tsnet.Server{Dir, Hostname, AuthKey, ControlURL, Logf, Store}`, `Start()`, `Loopback()`, registers the fallback handler. Returns "" or an error. |
| `nativeTsStatus()` | JSON: `state` (NeedsLogin / Starting / Running / Stopped), `authUrl`, `self{ips,dnsName}`, `magicDnsSuffix`, `peers[{hostname,dnsName,ips,online}]`, `socksPort`, `socksPassword`. Polled by the service every 5 s while starting, 30 s after. |
| `nativeTsIsTailnetHost(host)` | True for 100.64/10, the ts ULA, names ending in the MagicDNS suffix, or a bare label equal to a peer's hostname. Keeps the peer table in Go (refreshed from the IPN bus). |
| `nativeTsNetworkChanged()` | `Sys().NetMon.InjectEvent()`. |
| `nativeTsLogout()` / `nativeTsStop()` | `LocalClient().Logout` (removes the node from the tailnet) / `Close()`. |

Details:

- **Inbound handler**: accept when `dst` is one of our tailnet IPs, copy both ways with the existing
  `relay`/`closeWrite` helpers. Where to dial matters: with the real Tailscale app a peer only reaches services bound to
  `0.0.0.0`; dialing `127.0.0.1:port` would also expose loopback-only services (Termux API, debug servers, app IPC).
  So "all ports" dials the TUN's own address (`HevConfig.TUN_V4`, delivered locally by the kernel, accepted only by
  `0.0.0.0` listeners; verify local delivery from the excluded app in the spike), and `127.0.0.1` is used only for ports
  on an explicit allow-list (`inboundPorts`). Catch-all loopback is never the default.
- **State store**: tsnet's default is a plain file `Dir/tailscaled.state` holding the node private key. Invariant 8
  wants Keystore-encrypted secrets, so: Kotlin generates a random 32-byte key in `SecretStore`, passes it to
  `nativeTsStart`, and Go implements `ipn.StateStore` (ReadState/WriteState/`All`) as an AES-GCM-encrypted file under
  `filesDir/tailnet/`. The node key never leaves the device and never goes into a backup (same principle as invariant 7:
  per-install device keys). The shortcut, a plain FileStore in `filesDir`, is acceptable for the spike only.
- **Hostname**: `resproxy-<model>` plus a per-install suffix (several Android users on one phone each get a node).
- **Logging**: `Logf` → the diagnostics log at warn level; logtail off.
- Build: the Gradle `buildWgBridge` task gains the `-tags` list; Go tests under `./cmd/... ./internal/...` stay
  cgo-free. Add `tailnet_test.go` using tailscale's in-process fake control server
  (`tstest/integration/testcontrol`): two tsnet nodes, one dials the other through the loopback SOCKS5 and hits the
  fallback handler.

## Phase 3: Kotlin

- **Settings** (`Models.kt`, `shared/FORMAT.md`, Chrome `normSettings`, iOS `Models`, vectors regenerated):
  `tailnet: { enabled: false, hostname: "", controlUrl: "" (empty = Tailscale), inboundPorts: [] }`. The auth key is a
  secret in `SecretStore` (used once at login, then discarded; reusable keys are kept for re-login after expiry).
  Backups carry the settings, never the node state.
- **Service** (`ProxyVpnService`): start tsnet after the relay is up (before or after the TUN doesn't matter; it needs
  no TUN); stop it in Disconnect. Status polling feeds `TunnelState` (`tailnet: NeedsLogin/Connecting/Up(ip, name)/Error`).
  Network-change callback → `nativeTsNetworkChanged()`. The `health:` log line gets a `tailnet:` summary; a `Tailnet:`
  line at start names the node and control server. tsnet errors are logged, shown, never `fail()`.
- **Relay dispatch** (`LocalSocksServer.connect`): the tailnet check comes **first**, before the gate (tailnet traffic
  is not internet, it must work in PROXY_DOWN and before the first clean check), before `health` (an offline peer must
  not trip auto-repair) and before `LanTargets` (a bare MagicDNS name like `nas` is otherwise a "local name"). When
  `Tailnet.isTailnetHost(host)` and tsnet is Running: `Socks5Client.open` to `127.0.0.1:<socksPort>` with `tsnet` /
  password, then `relay()`. Not Running: reply 4 (host unreachable), so apps fail fast instead of hitting the proxy
  with a 100.x address. `udpAssociate` unchanged.
- **Keep tailnet sessions out of the proxy's bookkeeping.** `blockTraffic()` (every rotation, new IP, bad verdict)
  calls `closeConnections()`, which closes every socket in the relay's `open` set: tailnet SSH/HTTP sessions would drop
  on each rotation. Track tailnet connections in a separate set (or tag them) so `closeConnections()` skips them, count
  their bytes separately from `bytesUp`/`bytesDown` (they are not proxy usage), and don't count them in
  `health.accepted` / success / failure.
- **Proxy-only mode**: `LocalHttpProxy` gets the same tailnet branch, or proxy-only mode is documented as having no
  outbound tailnet access. **Split modes**: only apps inside the VPN reach the tailnet (excluded apps in
  `EXCEPT_SELECTED`, unselected ones in `ONLY_SELECTED` have no route to 100.64/10); say so on the Tailnet page.
- **Idle reachability**: peers see the phone offline while Android cuts the app's network in Doze; the Tailnet page
  points at Protection → "Run in the background" (the existing battery-optimization exemption).
- **UI**: Settings → Tailnet page (`SettingsPage.TAILNET`): switch, hostname, custom control URL (Headscale), auth-key
  field or a "Log in" button that opens the auth URL in a Custom Tab, status card (IP, DNS name, peers online, key
  expiry), inbound-ports list, "Log out of tailnet". Home screen: a small tailnet chip next to the VPN card.
- **Tests**: `LocalSocksServerTest` for dispatch ordering (tailnet before gate/LAN, reply 4 when down), `HevConfig` /
  `isFakeDnsIp` for the new range, `Routes` for the /48.

## Phase 4: polish / later

- UDP: relay-side UDP ASSOCIATE that routes per datagram (tailnet → tsnet `ListenPacket`/`Dial("udp")`, else the
  upstream's UDP relay when available). Needed for mosh, DNS to a tailnet resolver, QUIC apps.
- Subnet routes advertised by peers (dispatch by the peer's `PrimaryRoutes`; clashes with LAN bypass ranges need a rule).
- Using the phone as an exit node for other tailnet devices (they would get the residential IP). tsnet does not forward
  inbound packets from peers out of the box; needs its own spike.
- Key expiry handling (`NeedsLogin` again after 180 days): notification + re-login flow.
